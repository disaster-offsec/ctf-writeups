# Writeup — РакушкаBreach (SolarCTF 2026)

**Категория:** forensics
**Дата:** 2026-10-17
**Цель:** `disk.vhd` (10.5 МБ)
**Флаг:** `SOLARCTF{sh3llb4g_m4nual_pars1ng_is_th3_w4y}`

## Условие

Дан образ диска `disk.vhd`. В ходе расследования необходимо найти следы утечки данных, понять, какая программа и куда отправила информацию, и извлечь скрытый флаг.

## Разведка

1. **Идентификация контейнера.** Утилита `file` определяет файл как VHD. В первых 512 байтах стоит сигнатура `conectix`, а в заголовке — `cxsparse`, что указывает на динамический (разреженный) виртуальный диск. Для работы с ним нужно конвертировать VHD в сырой образ (raw), применив таблицу распределения блоков (BAT).
2. **Разбор файловой системы.** В MBR одна запись: тип `0x07` (NTFS), начало на секторе 128. Бут-сектор NTFS дает размер кластера (4096 байт) и точку старта таблицы `$MFT` (кластер 5370).
3. **Анализ дерева файлов.** Из `$MFT` извлекаются имена, размеры и атрибуты всех файлов. Удаленных записей нет — автор просто не оставил лишнего. В глаза бросаются файлы `notes.txt` (с паролями), `todo.txt`, ярлыки `.lnk` в папке `SolarGrid\Export`, а также необычный `diag_perfmon.edb` в `ProgramData\Microsoft\Diagnosis`.
4. **Сбор ключей.** В текстовых файлах (хранятся резидентно в MFT) найдены пароли: `s0lar_backup!!` и `dr0pp3d_th3_k3y`. Ярлык `.lnk` содержит сетевой путь `\\192.168.50.10\drop\solar_docs`.

## Уязвимость

1. **Аномалии в реестре и файлах.** Файл `NTUSER.DAT` (12 КБ) имеет нулевой заголовок (вместо `regf`). Строки выдают повторяющийся паттерн. Это XOR-шифрование, ключ к которому (`dr0pp3d_th3_k3y`) найден в заметках.
2. **Несовпадение форматов.** Файл `report_q3.xlsx` занимает всего 44 байта и не начинается с магии `PK` (zip). Значит, это не таблица, а зашифрованный контейнер с флагом.
3. **Утечка через SRUM.** Файл `diag_perfmon.edb` — это база SRUM (System Resource Usage Monitor), но у нее испорчен заголовок. Внутри содержатся записи о сетевой активности. Наибольший исходящий трафик у процесса `solarsync.exe` (~48 МБ).

## Эксплуатация

1. **Анализ ShellBags.** Расшифровка `NTUSER.DAT` ключом `dr0pp3d_th3_k3y` вскрывает куст реестра. В ShellBags видны папки `SolarGrid\Export`, а значение `PerfLogPath` указывает на `diag_perfmon.edb`.
2. **Парсинг SRUM.** База `.edb` разбирается вручную постранично (из-за битого заголовка). В сетевой таблице находим запись: `solarsync.exe` отправил 50 753 567 байт 15 сентября 2024 в 14:30.
3. **Криптоанализ XOR.** Берем зашифрованный `report_q3.xlsx` и применяем метод Known-Plaintext: так как флаг всегда начинается с `SOLARCTF{`, ксорим первые 9 байт файла с этими символами. Получаем ключ: `aa bb cc 11 22 33`. Повторяем ключ на всю длину файла и получаем исходный текст.

## Воспроизведение

Для решения использовался Python (без внешних библиотек) для ручного разбора структур. 

**Разбор VHD и MFT:**
```python
# Динамический VHD: чтение таблицы блоков
doff = struct.unpack('>Q', foot[16:24])[0]
f.seek(doff); h = f.read(1024)
bat_off = struct.unpack('>Q', h[16:24])[0]
n_blocks = struct.unpack('>I', h[28:32])[0]
# ... чтение байтов по смещениям (bps * spc) ...
```

**Расшифровка контейнера с флагом:**
```python
ct = open('report_q3.xlsx', 'rb').read()
crib = b'SOLARCTF{'
key = bytes(c ^ p for c, p in zip(ct, crib)) # aa bb cc 11 22 33
# ключ повторяется, применяем ко всем 44 байтам
```

**Результат:**
После расшифровки получаем читаемую строку:
`SOLARCTF{sh3llb4g_m4nual_pars1ng_is_th3_w4y}`

## Вывод

Этот таск отлично демонстрирует методологию форензики: от общего к частному. Ключевую роль сыграли не столько готовые инструменты (которые ломались на битых заголовках), сколько структурный анализ (сверка магии файлов с расширением) и криптоанализ по известному тексту. Ключ к флагу лежал в цепочке: текстовые заметки -> XOR-ключ для реестра -> ShellBags -> SRUM -> шифрованный файл.
