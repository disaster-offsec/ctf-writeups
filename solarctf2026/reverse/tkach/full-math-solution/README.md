# Writeup — Ткач / Weaver (SolarCTF 2026)

**Категория:** reverse
**Дата:** 2026-10-17
**Цель:** https://weaver.solarctf.ru (`glyphs.otf`, `glyphs.png`)
**Флаг:** `SOLARCTF{g1yph5_f0nt_gr33d}`

## Условие

Дана картинка `glyphs.png` (разноцветное месиво из перекрывающихся закорючек) и веб-страница с полем ввода. На странице подключён кастомный шрифт `glyphs.otf`, и включены OpenType-фичи `"calt" 1, "ss01" 1`. При вводе текст рендерится этим шрифтом. Эталонная картинка — это рендер скрытого флага `SOLARCTF{…}`. Задача — восстановить середину флага.

## Разведка

Вся логика клиента находится в одной HTML-странице и в самом шрифте:
1. Строка оборачивается в `"[" + text + "]"` (пустые граничные глифы запускают контекстные замены).
2. Разбор шрифта через `fontTools` (или в нашем случае через написанный с нуля Go-парсер) показывает, что `glyphs.otf` — это не обычный шрифт, а **конечный автомат**:
   - Таблица `GSUB` содержит 523 правила. Фича `calt` = lookup 0 + lookup 261, фича `ss01` = lookup 522.
   - Lookup 0 (слева направо) меняет глиф в зависимости от предыдущего: `F[j] = T(F[j-1], c[j])`. Функция `T` — латинский квадрат (биекция по состоянию и символу).
   - Lookup 261 (справа налево) меняет глиф в зависимости от правого соседа: `H[j] = R(F[j], H[j+1])`.
   - Lookup 522 (ss01) склеивает пары глифов.
   - GPOS (kern) задаёт шаг между глифами 300 единиц, при этом ширина глифа ~2000. Из-за этого слои сильно накладываются друг на друга с прозрачностью α≈0.66.

## Уязвимость

Шрифт вычисляет выходной глиф на основе **всех** символов строки (префикса и суффикса). Визуально это выглядит как хеш — прочитать отдельные буквы невозможно. 
Однако автомат построен обратимо: зная пару соседних выходных глифов `(H[j], H[j+1])`, можно однозначно восстановить внутреннее состояние `F[j]`, а по паре состояний `(F[j-1], F[j])` — сам символ `c[j]`.

## Эксплуатация (Анализ через синтез)

Так как прочитать глифы «глазами» нельзя, используется подход «черного ящика» с математическим вычитанием слоев:
1. **Рендеринг:** Реализуется точная копия рендеринга браузера (парсинг CFF-контуров, растеризация с антиалиасингом, наложение слоев с альфой, учет кернинга).
2. **Геометрия:** Длина флага `n=27`, масштаб `S=177.5` px/em и базовая линия `Yb=602` подбираются автоматически по правому краю картинки.
3. **Beam Search справа налево:**
   - Самый правый глиф лежит поверх всех, его слои видны целиком.
   - Для каждого кандидата (двух символов `c_x, c_{x-1}`) вычисляется, какой цвет должен был быть «под» уже известными глифами: `Under = (ref - Over_color) / (1 - alpha)`.
   - Если кандидат верный, полученный цвет попадает в диапазон `[0, 255]`. Если неверный — математическая невязка резко возрастает.
   - Оставляем ТОП-3 гипотезы (beam width = 3) и идем дальше влево, пока цепочка не замкнется на префиксе `SOLARCTF{`.

## Воспроизведение (Go, stdlib-only)

Для скорости и удобства алгоритм был портирован на Go (без внешних зависимостей). Программа сама парсит OTF, строит таблицы автомата, подбирает геометрию и запускает поиск. Полный код доступен в архиве, ниже приведены ключевые фрагменты.

**Парсинг GSUB (gsub.go):**

```go
// Применение цепочки замен для контекстного автомата
func (l *Layout) trySub(buf []uint16, st *subtable, pos int) int {
	g := buf[pos]
	switch st.typ {
	case 6:
		if _, ok := st.cov[g]; !ok {
			return 0
		}
		c := st.inCD[g]
		if c >= len(st.chainSets) {
			return 0
		}
	rules6:
		for _, r := range st.chainSets[c] {
			// ... проверка контекста (backtrack, input, lookahead) ...
			for _, rec := range r.recs {
				l.applyAt(buf, rec.lookup, pos+rec.seq)
			}
			return 1 + ni
		}
	}
	return 0
}
```

**Оценка кандидатов (raster.go):**

```go
// FeasScore: суммарное нарушение допустимости кандидата, лежащего под `ab`.
func FeasScore(f *Font, ref *Img, ab *Above, ls []Layer, thr float32) float64 {
	// ... (расчет bounding box и композиция слоев) ...
	for y := 0; y < h; y++ {
		for x := 0; x < w; x++ {
			// ...
			den := m * sc.Mc[j]
			for c := 0; c < 3; c++ {
				num := ref.Pix[i*3+c] - ab.B[i*3+c] - m*sc.Bc[j*3+c]
				v := float32(0)
				if -num > v { v = -num }
				if num-255*den > v { v = num - 255*den }
				total += float64(v)
			}
		}
	}
	return total / 1000
}
```


## Вывод

OpenType GSUB/GPOS — это мощный язык, позволяющий реализовать полноценный конечный автомат прямо внутри шрифта. Перекрытие и полупрозрачность защищают от простого чтения символов глазами, но не спасают от алгоритмов поиска. Тот факт, что автомат оказался обратимым (латинский квадрат), в сочетании с известным префиксом и возможностью математически вычитать слои, позволяет восстановить исходную строку методом Beam Search без полного перебора.
