**Цель:** `generate.py`, `output.txt`
**Флаг:** `SOLARCTF{31a1e6f428f7b196ac1fe4}`

## Условие

Дан скрипт генерации и файл с выходными данными. В файле: 4 независимых RSA-2048 (e=65537), для каждого модуля утекли старшие 518 бит одного из простых чисел (p или q). Каждое зашифрованное сообщение состоит из 24 случайных байт и 8 байт флага (всего 32 байта). Необходимо расшифровать сообщения и собрать флаг.

## Разведка

Анализ `generate.py` показывает, что генерация ключей и шифрование выполнены корректно (используется `secrets` для ГСЧ, исключены общие делители, `e` стандартное). Единственная аномалия — строчка:
`h = leaked >> (1024 - 518)`
Это **утечка частичного ключа**: мы знаем старшие 518 бит одного из 1024-битных простых чисел. Восстановить секрет можно с помощью атаки Копперсмита (Partial Key Exposure).

## Уязвимость

1. **Атака Копперсмита.** Пусть \(p = a + x\), где \(a = h \cdot 2^{506}\) — известная часть, а \(x < 2^{506}\) — неизвестная. Мы ищем малый корень многочлена \(f(x) = x + a\) по модулю \(p\), который делит \(N\). 
2. **Теоретическая граница.** Метод Копперсмита (через LLL-редукцию решеток) находит неизвестную часть, если она меньше \(N^{1/4}\). Для 2048-битного \(N\) это \(2^{512}\).
3. **Нехватка запаса.** Нам неизвестно 506 бит. До границы в 512 бит остается всего 6 бит «запаса». Если строить одну огромную решетку (размерность ~89), LLL-редукция будет считаться десятки минут. Гораздо быстрее перебрать эти 6 бит (64 варианта) и построить решетку меньшей размерности (47), которая считается за ~40 секунд.

## Эксплуатация

1. **Перебор 6 бит.** Для каждого модуля перебираем 64 возможных значения для «подозрительных» 6 бит под утечкой. Для каждого варианта вычисляем \(a\) (центрируем относительно середины, чтобы уменьшить неизвестный кусок до 499 бит).
2. **Построение решетки.** Для параметров \(m=23, t=24\) строим базис решетки из многочленов \(N^{m-i} f(x)^i\) и \(x^j f(x)^m\), масштабируя коэффициенты на \(X^k\) (где \(X = 2^{499}\)).
3. **LLL-редукция.** Запускаем LLL-алгоритм (через `fplll` или `fpylll`). Если перебор попал на правильные 6 бит, LLL найдет короткий вектор, который соответствует многочлену с корнем над целыми числами.
4. **Поиск корня.** Извлекаем этот многочлен, находим его целый корень \(x_0\) (через `numpy.roots` для приближения и метод Ньютона для точности). Вычисляем \(p = a + x_0\).
5. **Расшифровка.** Проверяем, что \(N \bmod p == 0\). Находим \(q = N / p\), затем закрытый ключ \(d = e^{-1} \bmod \phi(N)\). Расшифровываем \(m = c^d \bmod N\).
6. **Сборка флага.** Берем последние 8 байт каждого из 4 расшифрованных сообщений и склеиваем их.

## Воспроизведение

Для решения требуется Python 3 и установленный `fplll-tools` (или библиотека `fpylll`).

**Фрагмент построения решетки (из solve.py):**
```python
# f(x) = a + x
f = [a, 1]                                   
fpow = [[1]]
for _ in range(m):
    fpow.append(poly_mul(fpow[-1], f))

# Многочлены: N^(m-i)*f^i и x^j*f^m
polys  = [[N**(m - i) * c for c in fpow[i]] for i in range(m)]
polys += [[0] * j + fpow[m] for j in range(t)]

# Масштабирование на X^k
basis = [[p[k] * X**k for k in range(n)] for p in padded(polys)]

# LLL-редукция
short = lll(basis)[0]
g = [short[k] // X**k for k in range(n)] # Искомый многочлен
```

**Расшифровка и сборка:**
```python
# Допустим, p найден
q = N // p
phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)
m_int = pow(c, d, N)
m_bytes = m_int.to_bytes(32, 'big')

# Берем последние 8 байт
flag_parts.append(m_bytes[24:]) 
```

## Вывод

Данная задача — классический пример **Partial Key Exposure** в RSA. Ключевой навык здесь — не просто знать про метод Копперсмита, а уметь оценивать «запас прочности» (сколько бит мы можем отыграть решеткой). Из-за того, что неизвестных бит было всего на 6 меньше теоретического предела, оптимальной стратегией стал не «раздув» решетки до космических размеров, а комбинация перебора (brute-force) и LLL-редукции малой размерности.
