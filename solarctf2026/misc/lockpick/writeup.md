# Writeup — Локпик / Lockpick (SolarCTF 2026)

**Категория:** hardware / reverse
**Дата:** 2026-10-17
**Цель:** `lockpick.bin` (32 220 байт)
**Флаг:** `SOLARCTF{5pl1t_l0ck_g0es_brr}`

## Условие

Дан единственный файл `lockpick.bin` — перехваченный bitstream устройства, которое требует 32-битный ключ для разблокировки. Необходимо найти флаг.

## Разведка

1. **Идентификация файла.** Утилита `file` говорит просто `data`. Смотрим первые байты: `FF 00 00 FF 7E AA 99 7E` — это преамбула Lattice iCE40 (у Xilinx `AA 99 55 66`, у ECP5 `FF FF BD B3`). Энтропия 1.6 бит/байт и 85% нулей подтверждают, что это конфигурация ПЛИС, а не шифротекст.
2. **Распаковка.** С помощью Project IceStorm (`iceunpack` и `icebox_vlog.py -l`) файл конвертируется в текстовый `.asc` и затем в Verilog-нетлист. Внутри: 813 LUT, 105 триггеров, 1 блок BRAM (512x8, ROM на 256 байт), 35 входов, 15 выходов.
3. **Черный ящик.** Написан симулятор нетлиста. Подача сигналов показала:
   - `pin_49` — такт;
   - `pin_22` — сброс (активный 1);
   - `pin_134` — сигнал «старт» (без него все выходы нули);
   - остальные 32 пина — ключ;
   - `pin_41` — выход «разблокировано». При случайных ключах он всегда равен 0.

## Уязвимость

1. **Комбинационная проверка ключа.** Логический конус `pin_41` зависит только от 32 пинов ключа, не содержит триггеров или памяти. Это чистая функция из XOR-ов и цепочек переноса. Ключ при этом единственный.
2. **Ключ — не флаг.** Найденный ключ лишь «открывает замок». Флаг схема выдаёт на выходах после разблокировки: 29 байт на 8 пинах данных, по 2 такта на байт.
3. **Порядок пинов не задан.** Какой пин отвечает за какой бит в байте, неизвестно, но префикс формата `SOLARCTF{` даёт готовый known-plaintext для сопоставления.

## Эксплуатация

1. **Поиск ключа.** Логика `pin_41` переводится в КНФ (по Tseitin) и решается SAT-солвером (CaDiCaL) либо перебором bit-slicing-ом. Найдено ровно одно решение (запрет дал UNSAT). В виде строки (пины по возрастанию): `11100100000111001010011000000101` = `0xe41ca605`.
2. **Анализ выходов.** С верным ключом последовательность чтений из ROM фиксирована. Дифференциальный тест (переворот бита в ROM) показал: данные идут по 8 пинам (32, 34, 33, 39, 42, 44, 45, 135) на тактах 2, 4, ..., 58.
3. **Сборка ASCII.** Для каждого бита байта ищем пин, чей поток в первых шагах совпадает с битами `SOLARCTF{`. Получаем маппинг:
   ```text
   бит0 pin_135   бит1 pin_42   бит2 pin_44   бит3 pin_32
   бит4 pin_45    бит5 pin_39   бит6 pin_34   бит7 pin_33
   ```

## Воспроизведение

Требуется Python 3.8+ и утилиты IceStorm (в Linux ставятся через `sudo apt install fpga-icestorm`).

```bash
iceunpack lockpick.bin lockpick.asc
icebox_vlog.py -l lockpick.asc > lockpick.v
python3 solve.py --verilog lockpick.v
```

Скрипт `solve.py` парсит Verilog, находит ключ, симулирует и читает выходы. Суть сопоставления пинов:

```python
for b in range(8):
    cand[b] = [o for o in outputs if o != unlock
               and all(steps[i][o] == (prefix[i] >> b) & 1 for i in range(len(prefix)))]
for pick in itertools.product(*cand):
    text = bytes(sum(st[pick[b]] << b for b in range(8)) for st in steps)
    if all(32 <= x < 127 for x in text):
        print(text.decode())
```

Ожидаемый вывод:
```text
выход «разблокировано»: pin_41
ключ (пины по возрастанию): 11100100000111001010011000000101 = 0xe41ca605
pin_41 = 1 (ожидали 1)
ФЛАГ: SOLARCTF{5pl1t_l0ck_g0es_brr}
```

## Вывод

Главная ловушка таска — принять найденный 32-битный ключ за флаг. Платформа не приняла hex-значения (`e41ca605`), что подсказало: ключ лишь открывает замок, а данные нужно читать с выходов схемы. Hardware-таски надёжнее всего решать через черный ящик (поиск такта, сброса, старта) и анализ конуса влияния, а SAT-солверы и дифференциальные эксперименты ускоряют процесс.
