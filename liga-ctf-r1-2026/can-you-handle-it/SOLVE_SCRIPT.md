# solve.py — инструкция к скрипту

Скрипт — это **автоматизация пути из `README.md`**. В райтапе всё сделано
руками и инструментами (`strings` → `grep -obUaP` → one-liner → декод);
`solve.py` нужен, когда путь уже понятен и хочется прогнать его одной
командой — например, чтобы перепроверить себя или повторить на другом дампе.

## Что нужно

- Python 3 (любая свежая версия), только стандартная библиотека, без `pip`.
- Файл дампа `suspicious_full.dmp`. Опционально `disk.vhdx` для сверки.

## Запуск

```bash
# минимум: только дамп
python3 solve.py suspicious_full.dmp

# со сверкой по образу диска
python3 solve.py suspicious_full.dmp --disk disk.vhdx

# флаг пишется в FLAG.txt (имя можно поменять)
python3 solve.py suspicious_full.dmp --out FLAG.txt
```

## Что скрипт делает по шагам

1. **Парсит minidump**: заголовок, каталог потоков, `Memory64List`
   (374 диапазона «VA → где лежат данные в файле дампа»).
2. **Достаёт параметры** (ключ / смещение / длина), тремя способами по
   убыванию честности:
   - pinned-строка `cfg:xor=...;off=...;len=...;path=...` из кучи — при этом
     пробует **оба выравнивания UTF-16**: Windows положила её на нечётный
     байт (грабелька, см. ниже), и цельный декод с начала файла её сдвигает;
   - командная строка процесса (UTF-16 и ASCII);
   - если и там пусто — брутит ключ 1..255 по префиксу `flag{`.
3. **Сканирует память** на `enc('flag{') = 'flag{' ^ key`, декодирует
   `--flag-length` байт, отсеивает `flag{decoy-...}` приманки и печатает
   каждое вхождение с файловым смещением и виртуальным адресом.
4. **`--disk`**: ищет те же байты в образе диска и сверяет результат с дампом.

## Грабельки, которые учтены внутри

- **cfg-строка лежит на нечётном смещении** (`0x430bbaf`) — поэтому декод
  UTF-16 выполняется с фазой 0 и фазой 1;
- длина UTF-16-строки обязана быть чётной (иначе `decode` падает);
- приманки отфильтровываются по подстроке `decoy-`, а не по счётчику;
- параметры из cmdline парсятся как `--xor-key 252`, так и `--xor-key=252`.
