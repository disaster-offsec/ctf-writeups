# Сработка: теория

## What is it

Обход сигнатурного детекта (NIDS / фильтр-«стенд») через **stateful-обфускацию
полезной нагрузки**. Правило ищет 16-байтовую сигнатуру в событиях; после
обновления клиента (r9) те же события кодируются самодельным поточным шифром,
чей keystream зависит от состояния сессии: mode, nonce-зерно, счётчик принятых
событий, crc32-ratchet. Одинаковое содержание → разные байты в каждом запросе,
поэтому «сравнение запросов» перестаёт что-либо объяснять.

## How it works

Условия возможности — через «чему доверяет приложение»:

- детект доверяет сырым байтам запроса: канонизации/декодирования перед
  матчингом нет;
- схема шифрования публична: код клиента отгружается браузеру и попадает
  в дамп — Kerckhoffs, «секрет» только в состоянии сессии;
- всё состояние выводимо из наблюдаемого трафика: `seed` из nonce в `/open`
  и `/reset`, `seq` по принятым событиям, дельта по заголовку `x-ratchet`,
  коммуты `/switch` по `x-commit`, `crc32` по телу запроса (CRC — не MAC).

Реальный запрос из задачи (порт 53011):

```http
POST /gate/v3 HTTP/1.1
Host: gate.filter.local
X-Request-ID: d10
X-Probe-Client: /assets/probe-session.r9.js
Content-Length: 64
Connection: keep-alive

PuapjIqQHrjIpA+LZiVEXH0qGbBTKFxg/xIk9zF0SHNsh4tTZQ5fOuFxScSG4Yx8
```

Упаковка (из клиента r9): 3 слота × 16 байт, перестановка блоков по mode,
сдвиг внутри блока от seed/seq, XOR байта 32-битного LCG
(`x = x*1664525 + 1013904223`) и соли слота. Сигнатура дополнительно
«размыта»: она равна XOR двух блоков телеметрии, поэтому не видна и после
декодирования — пока не сопоставишь события между собой.

## Impact

- Атакующий скрывает известные маркеры (сигнатуры эксплойтов, C2-метки)
  от сигнатурного фильтра, не меняя смысла трафика: детект слепнет целиком.
- Аналитик без кода клиента или без полного дампа (обрыв сессии → нет
  seed/seq) сигнатуру не восстановит.
- Цепочки: + TLS — байтов для инспекции нет вовсе; + подмена дедупликации
  (ре-доставка = «то же измерение») — учёт событий дрейфует.

## Defenses

1. Канонизация перед матчингом: детект по декодированной телеметрии,
   версия клиента пиннится, расшифровка — в аналитическом конвейере.
2. Стандартная крипто вместо самоделки: TLS + AEAD/HMAC; 32-битный LCG
   обратим, crc32 подделываем — это обфускация, не защита.
3. Что включено «по умолчанию» в корректных системах: серверные
   идентификаторы событий вместо клиентских порт+ID, идемпотентные
   дедуп-ключи, точная семантика повторов (204/208).

## Why defenses break

- bypass 1: правило знает одну форму кодирования — новая ревизия клиента
  меняет порядок блоков и соли, и правило «перестаёт объясняться простым
  сравнением запросов», пока сессию не проиграешь заново.
- bypass 2: состояние восстанавливаемо: 32-битный LCG предсказуем, nonce
  отдаётся в ответе, ratchet — в заголовке; атакующий сам направляет
  траекторию (409 на `/switch` — выбрать неудобный для стенда режим).
- bypass 3: семантика повторов: повторная доставка (`208 Already Reported`)
  не является новым измерением и не двигает состояние — этим можно сбивать
  учёт и матчинг.
