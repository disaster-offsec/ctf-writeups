## TL;DR

QR-код на чеке сканируется без ошибок, но 124 модуля в нём намеренно перевёрнуты — «помарки термопринтера». Декодер QR молча исправляет их кодами Рида–Соломона (31 испорченное кодовое слово), а величина каждого исправления (`принятое XOR исправленное`) — ASCII-символ. Ручной разбор QR версии 10-H и сортировка ошибок по позиции кодового слова дают `flag{S1l3nt_C0rr3ct10n_Ch@nn3l}`.

## Recon

- `file receipt.png` → PNG 520×520, **1-битный** grayscale. Чанки только `IHDR/IDAT/IEND`: метаданных нет, а 1-битность сразу убивает все идеи про LSB/zsteg — прятать биты в младших разрядах негде.
- Картинка — один QR-код: 57×57 модулей, 8 px на модуль, тихая зона 32 px (4 модуля) с каждой стороны: 57·8 + 64 = 520.
- Любой сканер читает его без единой жалобы:

```
https://check.norlanmarket.example/r?fn=9287440300841772&i=84172&fp=1937450211&s=1284.60&t=20260812T1947
```

  Декоративный «фискальный» URL (`fn/i/fp/s/t` — типовые поля чека). В самом URL ничего нет.
- Подсказка в легенде: «принтер печатал с помарками, но сканер не жаловался». Значит помарки лежат **внутри запаса коррекции ошибок** QR, и смотреть нужно не на то, что сканер декодировал, а на то, **что он молча исправил**.

## Steps

### 1. Снять модульную матрицу

QR напечатан ровной сеткой: режем картинку на блоки 8×8 px со смещением 32 px и голосуем по среднему.

```python
im = np.array(Image.open('receipt.png').convert('L'))
N, PX, OFF = 57, 8, 32
mat[r, c] = 1 if im[OFF+r*PX:OFF+(r+1)*PX, OFF+c*PX:OFF+(c+1)*PX].mean() < 128 else 0
```

Проверка сетки: finder-паттерны в углах `(0,0)`, `(0,50)`, `(50,0)` и timing-линии совпали с эталоном → матрица снята верно. Размер 57×57 = 17 + 4·10 → **версия 10**.

### 2. Прочитать format info → EC = H, маска 3

15 бит вокруг левого верхнего finder (старший бит первым), XOR с `0b101010000010010`, проверка BCH по порождающему полиному `0b10100110111`. Обе копии format info совпали и прошли проверку:

```
EC level: H   mask: 3
```

Уровень **H** — запас коррекции максимальный. Для v10-H это 28 EC-слов на блок, т.е. декодер молча исправляет до **14** кодовых слов в каждом блоке.

### 3. Снять маску и вычитать 346 кодовых слов

На всех «немаркированных» модулях снимаем маску 3 (бит инвертируется, если `(r+c) % 3 == 0`), затем читаем биты зигзагом: колонки парами справа налево, снизу вверх, пропуская функциональные модули (finders, timing, alignment, format/version info, dark module).

```
модулей данных: 2768 = 346 кодовых слов (v10-H: 122 данных + 224 EC)
```

### 4. Де-чередовать в 8 блоков и прогнать Рид–Соломона

v10-H: 6 блоков по 15 слов данных + 2 блока по 16, по 28 EC-слов в каждом. Чередование: 15 раундов по 8 блоков, +1 слово для блоков 6–7, затем 28 раундов по 8 EC-слов.

```python
rsc = RSCodec(28)
_, fixed, _ = rsc.decode(bytes(db[b] + eb[b]))   # блок: 43 или 44 байта
```

Санити: из исправленных слов данных собирается payload `mode=0100 (byte), count=104` → тот самый URL. Значит, декодирование принято корректно.

### 5. Величины ошибок = флаг

Сравниваем принятое слово с исправленным в каждом блоке. Расхождений ровно **31**, и величина каждой ошибки — печатный ASCII-символ. Порядок символов — глобальный индекс кодового слова в чередованном потоке (`p·8+b` для данных, `122+i·8+b` для EC-части):

```
6:'f' 14:'l' 21:'a' 28:'g' 29:'{' 46:'S' 50:'1' 54:'l' 55:'3' 69:'n'
73:'t' 84:'_' 97:'C' 100:'0' 104:'r' 121:'r' 165:'3' 185:'c' 210:'t'
226:'1' 228:'0' 253:'n' 257:'_' 261:'C' 275:'h' 277:'@' 282:'n'
314:'n' 320:'3' 324:'l' 341:'}'
```

Результат:

```
flag{S1l3nt_C0rr3ct10n_Ch@nn3l}
```

### 6. Проверка

Откатываем исправления в модули (каждая ошибка переворачивает 2–6 бит своего кодового слова): всего **124 модуля** отличаются от исходного чека — это и есть «помарки» (`fig1.png`, красным). Собранная «чистая» матрица сохраняется как `receipt_clean.png`: её синдромы Рида–Соломона во всех 8 блоках нулевые, и cv2-сканер читает из неё тот же URL.

## Why it works

Ментальная модель: **сканер доверяет кодовым словам Рида–Соломона, а не отдельным пикселям**. Любые искажения в пределах 14 слов на блок он исправляет молча — для него «помарки» не существуют, поэтому «чеки проходили сканер без единой жалобы». Наблюдатель, в свою очередь, доверяет итоговому payload и не сравнивает сырые модули с ожидаемыми. Секрет живёт в канале коррекции: в разнице между принятым и исправленным.

Два подводных камня, которые стоит знать:

- Наивное сравнение «пересобрал QR с тем же URL и сделал diff матриц» шумит: другой кодировщик иначе заполняет терминатор и паддинг, и в эталоне отличались бы 70 кодовых слов, из которых стегосообщение — только 31. Надёжный путь — RS-декодировать именно принятый поток и смотреть errata.
- Одна помарка — не одиночный модуль: автор переворачивал 2–6 модулей одного кодового слова, поэтому «вручную глазами» отследить биты нереально, нужен полный разбор.

## Defense

1. **Логировать исправления.** Декодер и так знает, какие слова починил (errata). У честно напечатанного QR исправлений быть не должно: ненулевая статистика коррекции на «чистом» носителе — красный флаг.
2. **Re-encode & diff по кодовым словам.** Пересобрать слова из payload и сравнить с принятыми уже *после* RS-декодирования — осмысленные различия выдают скрытый канал.
3. **Подпись полезной нагрузки.** Если URL+данные подписаны (как в реальных фискальных чеках, где поля проверяются сервером ОФД/ФНС), подмена кодовых слов либо ломает подпись, либо бессмысленна.
