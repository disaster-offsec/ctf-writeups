Стенд обмена, ревизия 3

exchange.wasm — тот же вычислитель, которым получен capture.json. Импортов
нет. Экспорты доступны в любом совместимом WebAssembly runtime.

В линейной памяти по адресу 0 находятся 16 байт p, по адресу 16 — 16 байт g.
Все математические числа на входе и выходе записываются big-endian.
Для своих буферов используйте свободную область 2048..8191.
Память 544..639 служебная; область от trace_ptr занята регистратором.

Экспорты:
  memory — линейная память;
  powmod(base_ptr, exponent_ptr, modulus_ptr, result_ptr) — b^e mod p;
  run(base_ptr, exponent_ptr, modulus_ptr, result_ptr, tag) — запуск стенда;
  trace_reset() — сброс счётчика и внутреннего состояния регистратора;
  trace_ptr — адрес начала диагностической области;
  trace_len() — её текущая длина в байтах;
  keystream_xor(key_ptr, data_ptr, length) — XOR на месте с циклическим
    16-байтовым ключом. Нулевая длина допустима.

Входной base должен быть меньше модуля, большего 1. Показатель занимает
до 128 бит. Буферы не должны пересекаться со служебной областью или друг с
другом. Диагностический буфер рассчитан на 512 записей между сбросами.

capture.json сохраняет порядок вызовов run после одного trace_reset.
operations: метка, 32-битный tag, base, известный показатель либо null,
результат. Числа base, exponent, result представлены hex строками по 16 байт.
Контрольные операции имеют известные показатели; в обменах они не сохранены.

trace_words — диагностическая область после всех вызовов: каждые 8 байт
прочитаны как два unsigned little-endian uint32, tag и word. Смысл word
в документации регистратора не сохранился. Перезапускайте вычислитель с
собственными входами, чтобы проверить предположения о его поведении.

sessions связывает пары открытых значений: A=g^a mod p и B=g^b mod p.
Для указанного target общий ключ K=B^a=A^b mod p записан строго 16 байтами
big-endian и повторяется при XOR с ciphertext. У разных сеансов показатели
различаются. Все необходимые данные находятся в выдаче; подключение к сети
или исходный код стенда не нужны.
