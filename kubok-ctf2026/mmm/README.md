## 1. Задание и вводные

В архиве `mmm.zip` лежит один файл — `mmm`. Утилита `file` сообщает: **ELF 64-bit, PIE, динамический, собран компилятором C++ (g++), символы не вырезаны (not stripped)**. Последнее — большая удача: в таблице символов останутся имена функций и глобальных данных автора задания.

Запуск без аргумента печатает `usage: %s` — программа ждёт **один аргумент командной строки**, который в текстах задания назван «подношением».

У бинарника ровно три сообщения-исхода, и они же — подсказки:

| Сообщение | Что означает |
|---|---|
| `The mirror shows a stranger. Walk the same line as the glass` | провал проверки 1 |
| `Your shadow falls where it should, yet the seal does not know your name` | провал проверки 2 при пройденной первой |
| `The seal breaks. Carry what you brought to the gate` | полный успех |

Фразы не декоративные. Первая — провал «зеркальной» проверки, вторая — хеш не совпал, третья — победа. **«Идти по той же прямой, что и отражение» — почти дословное описание собственного вектора**: вектор и его образ под матрицей лежат на одной прямой.

## 2. Методология: как подходить к реверс-CTF

Любой крекмис устроен одинаково: есть предикат проверки `P(s)`, который на входе `s` возвращает «успех» или «отказ». Задача — найти `s`, на котором `P` истинно. Брутфорс почти никогда не нужен: предикат пишут так, чтобы он был **вычислим, а значит, и обратим** — хотя бы частично.

Правильный порядок действий экономит часы. Рабочий чеклист из шести шагов:

1. **Разведка.** `file`, `sha256sum`, `strings`, `nm`/`readelf`. Цель — понять язык, наличие символов, строки-подсказки и формат ожидаемого ввода (длина, алфавит, префикс флага).
2. **Классификация.** Найти функцию проверки и определить тип предиката: сравнение строк, посимвольные ограничения, XOR, хеш, арифметика, линейная алгебра, VM/Z3-система.
3. **Статический анализ.** Дизассемблировать только путь проверки (`objdump` по адресам из `nm`; при необходимости — Ghidra для псевдокода). Выписать ограничение на бумагу в математической форме.
4. **Переформулировка.** *Самый важный шаг.* «Попарное сравнение перекрёстным умножением» — это пропорциональность; «вектор, не меняющий направления» — собственный вектор. Термин из дизасма нужно перевести на язык, для которого есть готовый решатель.
5. **Решение.** Выбрать инструмент под задачу: `numpy`/`scipy` — для алгебры, `z3` — для систем ограничений, `angr` — для символического исполнения, радужные таблицы/хешрейт — для хешей с малой энтропией.
6. **Верификация.** Всегда прогнать найденный ответ через **сам бинарник**. Локальная модель проверки может отличаться от реальной (знак, порядок байтов, переполнение).

### Таблица 1. Базовый набор инструментов реверсера

| Инструмент | Назначение | Когда использовать |
|---|---|---|
| `file` / `sha256sum` | Тип, архитектура, PIE, stripped? | Первые 10 секунд |
| `strings` | Сообщения, подсказки, формат флага | Сразу после `file` |
| `nm` / `readelf` | Символы, адреса данных и функций | Если бинарь не stripped |
| `objdump -d -M intel` | Точный дизассемблер с адресами | Короткие функции проверки |
| Ghidra / IDA | Псевдокод, структуры, графы вызовов | Сложная логика, сотни строк |
| `gdb` + pwndbg | Динамическая отладка, дампы памяти | Проверить гипотезы в рантайме |
| `ltrace` / `strace` | Трассировка вызовов libc | Ввод-вывод, сравнения в libc |
| python: numpy, z3, angr | Решатели: алгебра, ограничения, символика | Этап 5 |

## 3. Разведка бинарника

`strings` сразу выдаёт приглашение ввода и три сообщения-исхода, а также строки `main.cpp` и имена вроде `_ZL6MATRIX` — это C++-манглинг: статическая переменная `MATRIX`.

`nm` подтверждает: бинарь не stripped, и все ключевые сущности разложены по адресам. Сегмент `.rodata` загружен с базы 0 (типично для PIE малых размеров), поэтому **виртуальные адреса совпадают с файловыми смещениями** — данные можно читать прямо из файла без запуска программы.

### Таблица 2. Ключевые символы nm и их смысл

| Символ | Адрес | Что это |
|---|---|---|
| `main` | `0x10d0` | Точка входа: две проверки по очереди |
| `check(char const*)` | `0x1230` | Проверка 1: «зеркальная», линейная алгебра |
| `hash_check(char const*)` | `0x14e0` | Проверка 2: SHA-256 от строки |
| `MATRIX` (static) | `0x3220` | Данные: 0x3200 байт = 40×40 int64 |
| `FLAG_HASH` (static) | `0x6420` | Данные: 32 байта целевого хеша |
| `Sha256::transform` K | `0x3100` | Таблица констант SHA-256 (64 слова) |
| `Sha256::reset` init | `0x3200` | Начальное состояние хеша (8 слов) |

Уже на этом этапе виден скелет решения: одна проверка опирается на большую матрицу (намёк на линейную алгебру), вторая — на хеш, который фиксирует единственный точный ответ. Остаётся понять математику первой и сверить константы второй.

## 4. main: две проверки

Функция `main` тривиальна и хороша как разминка: она принимает `argv[1]`, сначала зовёт `check()`, затем — `hash_check()`, и печатает одно из трёх сообщений. Ветвление восстанавливается по адресам переходов:

```asm
; main, дизассемблер (objdump -M intel), сокращено
10d0:  push   rbx
10d1:  mov    rbx,rsi
10d4:  cmp    edi,0x2
10d7:  je     10f1              ; нужен ровно 1 аргумент
10f1:  mov    rdi,QWORD PTR [rsi+0x8]   ; rdi = argv[1]
10f5:  call   1230              ; проверка 1 (check)
10fa:  test   al,al
10fc:  je     111b              ; 0 -> "The mirror shows a stranger"
10fe:  mov    rdi,QWORD PTR [rbx+0x8]
1102:  call   14e0              ; проверка 2 (hash_check)
1107:  test   al,al
1109:  je     1129              ; 0 -> "Your shadow falls..."
110b:  lea    rdi,[rip+0x1fb6]  ; "The seal breaks..."
1112:  call   1080
1117:  xor    eax,eax           ; return 0
```

### Таблица 3. Три исхода программы

| Условие | Адрес сообщения | Текст |
|---|---|---|
| `check()` вернула 0 | `0x3020` | The mirror shows a stranger... |
| `hash_check()` вернула 0 | `0x3078` | Your shadow falls where it should... |
| обе вернули 1 | `0x30c8` | The seal breaks. Carry what you brought... |

Псевдокод: `if (check(s) && hash_check(s)) win;` — **обе проверки получают одну и ту же строку**. Теперь вскроем каждую.

## 5. check(): собственный вектор матрицы

Первое, что делает `check()`, — измеряет длину: `strlen(s) == 0x28`, то есть **ровно 40 байт**. Далее два оператора `new` по 0x140 байт — это два массива из 40 int64. Первый — вектор `v`: SIMD-инструкции `punpcklbw`/`punpcklwd` разворачивают каждый байт строки в 64-битное число без знака, так что `v[i] = (unsigned char)s[i]`. Второй — вектор результата `r`.

Затем идёт двойной цикл, который на языке C выглядит так:

```asm
; умножение матрицы на вектор: r = M * v
1430:  mov    rcx,QWORD PTR [rdi]        ; rcx = r[i] (аккумулятор)
1438:  mov    rdx,QWORD PTR [rsi+rax*8]  ; rdx = MATRIX[i][a]
143c:  imul   rdx,QWORD PTR [rbx+rax*8]  ; rdx *= v[a]
1441:  add    rax,0x1
1445:  add    rcx,rdx                    ; r[i] += M[i][a] * v[a]
1448:  cmp    rax,0x28                   ; a < 40?
144c:  jne    1438
144e:  add    rsi,0x140
1455:  mov    QWORD PTR [rdi],rcx        ; r[i] = результат
1458:  add    rdi,0x8
145c:  add    r8,rsi
145f:  cmp    ..., 1430                  ; все 40 строк?
```

Это классическое умножение матрицы 40×40 на вектор: **r = M·v**, вся арифметика — целочисленная, знаковая (`imul`). Значения матрицы лежат в диапазоне примерно от −960 до 2141.

Дальше начинается самое интересное — финальная проверка результата:

```asm
; попарная проверка всех пар k < j
1467:  mov    rsi,QWORD PTR [r9+r8*8]    ; rsi = r[k]
146b:  test   rsi,rsi
146e:  setne  al
1475:  or     r12d,eax                   ; накапливаем флаг r != 0
147e:  mov    rdi,QWORD PTR [rbx+r8*8-0x8]  ; rdi = v[k]
1492:  mov    rcx,QWORD PTR [rbx+rax*8]  ; rcx = v[j]
1496:  mov    rdx,QWORD PTR [r9+rax*8]   ; rdx = r[j]
149a:  imul   rcx,rsi                    ; v[j] * r[k]
149e:  imul   rdx,rdi                    ; r[j] * v[k]
14a2:  cmp    rcx,rdx
14a5:  je     1488                       ; равны -> следующая пара
14a7:  xor    r12d,r12d                  ; не равны -> check() = false
```

Для каждой пары индексов `k < j` бинарник требует **`v[j]·r[k] == r[j]·v[k]`**. Это критерий коллинеарности, записанный через перекрёстное умножение — именно так его пишут, чтобы не делить на ноль. Плюс отдельное требование: `r` не должен быть полностью нулевым (накопление через `or`). Поскольку `s` — C-строка длиной 40, ни один её байт не равен нулю, поэтому все `v[i]` лежат в диапазоне 1..255.

**Итог перевода с ассемблера на математику:**

```text
M·v = λ·v   при λ ≠ 0
```

Входная строка должна быть **собственным вектором** матрицы `MATRIX`, а его компоненты — коды печатных ASCII-символов. Задача сводится к поиску целочисленного собственного вектора с ограничением `32 ≤ v[i] ≤ 126` — стандартная работа для `numpy.linalg.eig`.

## 6. hash_check(): SHA-256

Вторая проверка — длинная функция с раскрученным вручную SHA-256: класс `Sha256` с методами `reset`/`transform`, блок по 64 байта, дополнение длиной, `bswap` слов на входе.

**Свои реализации хешей в CTF часто содержат сюрприз**: подменённые константы или изменённые сдвиги. Поэтому первым делом я сверил две таблицы из `.rodata` с эталоном FIPS 180-4: `K` (64 слова по адресу `0x3100`) и начальное состояние `h` (8 слов по адресу `0x3200`). Обе — байт-в-байт стандартные, так что хеш считается обычный SHA-256.

Целевое значение `FLAG_HASH` по адресу `0x6420`:

```text
a25dc7ca4d6ee2f327c52ad487db20ff6846d7b512b83ffb0bb430f4cc124442
```

Роль второй проверки — зафиксировать **единственного кандидата**: собственных векторов у матрицы много (кратные любому найденному тоже подойдут), но лишь один из них имеет нужные ASCII-компоненты и именно такой хеш. Это типовая страховка автора задания от тривиальных решений.

## 7. Решение по шагам

Данные извлечены, условие понято. Последовательность атаки:

| Шаг | Действие | Результат |
|---|---|---|
| 1 | Прочитать `MATRIX` (12800 байт по `0x3220`) как 40×40 int64 | Матрица на руках |
| 2 | `numpy.linalg.eig(M)`: все собственные пары | 34 комплексные + 6 вещественных пар |
| 3 | Отобрать вещественные лямбды, среди них — круглое число | **1337.0000** (leet!) |
| 4 | Нормировать вектор: `w / max\|w\|` | Компоненты кратны 0.008 |
| 5 | Умножить на 125 и сменить знак | Целые числа 49..123 = ASCII-коды |
| 6 | Точная целочисленная проверка `M·u = 1337·u` | Пройдена без остатков |
| 7 | `sha256(строка)` vs `FLAG_HASH`, запуск бинарника | Совпадение, «The seal breaks» |

### Почему именно 1337 и масштаб 125?

После нормировки по максимальной компоненте все числа вида `0.008·k`: `0.984, 0.928, 0.792...` Это верный признак того, что подлинный вектор целый, а его максимальная компонента равна 125. Умножение даёт диапазон 49..123 — попадает в ASCII.

Собственный вектор определён **с точностью до знака**, а numpy вернул его отрицательным, поэтому берём `-w`. Точная проверка в целых числах (**не через float!**) обязательна: она исключает ошибки округления и повторяет логику бинарника один в один.

```python
# ядро решателя (полная версия — в 03_eigen_solver.py)
M = np.array(struct.unpack('<1600q', data[0x3220:0x3220+12800])).reshape(40, 40)
vals, vecs = np.linalg.eig(M)              # все собственные пары
for i in range(len(vals)):
    lam = vals[i]
    if abs(lam.imag) > 1e-6:               # комплексные пары — мимо
        continue
    w = np.real(vecs[:, i])
    w = w / np.max(np.abs(w))              # нормируем: max |w| = 1
    for S in range(1, 4000):               # ищем целый масштаб
        u = [int(round(x * S)) for x in w]
        for cand in (u, [-c for c in u]):  # знак не важен
            if min(cand) < 32 or max(cand) > 126:
                continue                   # вне печатных ASCII
            t = [sum(int(M[a][b]) * cand[b] for b in range(40))
                 for a in range(40)]       # r = M*v в целых числах
            if any(t) and all(cand[j] * t[k] == t[j] * cand[k]
                              for k in range(40) for j in range(k+1, 40)):
                flag = ''.join(chr(c) for c in cand)   # готово
```

Результат: `M·u = 1337·u`, масштаб ×125, собственное значение **1337** («leet») — авторский водяной знак.

## 8. Скрипты

Полный набор — четыре файла в папке `mmm_scripts/`. Каждый решает свою ступень пайплайна, их можно запускать по очереди; `04` — самодостаточный end-to-end вариант. Ниже — ключевые фрагменты с комментариями.

### 8.1 `01_recon.sh` — разведка

Первый скрипт любого реверса: собирает тип файла, строки, символы и полный дизассемблер в один заход.

```bash
#!/usr/bin/env bash
BIN="${1:-./mmm}"
file "$BIN"                                  # тип, архитектура, PIE, stripped?
strings -n 5 "$BIN" | head -80               # сообщения и подсказки
nm "$BIN" 2>/dev/null | head -60             # символы: функции и данные
readelf -h "$BIN" | head -14                 # заголовок ELF
objdump -d -M intel --no-show-raw-insn "$BIN" > disasm.asm
```

### 8.2 `02_extract_data.py` — извлечение данных

Читает `MATRIX`, `FLAG_HASH` и таблицы SHA-256 прямо из файла: у PIE с базой 0 адрес = смещение. Сверка `K` и `init` с эталоном отсеивает «испорченный» хеш.

```python
K      = struct.unpack('<64I', data[0x3100:0x3200])      # константы SHA-256
init   = struct.unpack('<8I',  data[0x3200:0x3220])      # h0..h7
M      = struct.unpack('<1600q', data[0x3220:0x3220+12800])  # 40x40 int64
MAT    = [M[i*40:(i+1)*40] for i in range(40)]
target = data[0x6420:0x6440]                 # FLAG_HASH, 32 байта
# печать: совпадает ли K с эталоном FIPS 180-4, диапазон значений матрицы
```

### 8.3 `03_eigen_solver.py` — универсальный решатель

Тот же алгоритм, что в главе 7, но оформлен как инструмент: размер матрицы определяется автоматически, диапазон ASCII и порог перебора масштаба — параметры. Подходит для любого крекмиса вида «строка = собственный вектор матрицы».

```python
def exact_eigvec_check(Mi, u):
    """Реплика проверки из бинарника в целых числах."""
    t = [sum(int(Mi[i][j]) * u[j] for j in range(n)) for i in range(n)]
    if all(x == 0 for x in t): return None              # r == 0 — fail
    for k in range(n):
        for j in range(k+1, n):
            if u[j] * t[k] != t[j] * u[k]: return None  # не параллельны
    return t[k] // u[k]                                 # собственное значение
```

### 8.4 `04_solve_and_verify.py` — всё сразу

Извлекает данные, находит флаг, сверяет SHA-256 и запускает сам бинарник с ответом. Запуск: `python3 04_solve_and_verify.py ./mmm`. Вывод на этом задании:

```text
[1] матрица 40x40 и FLAG_HASH извлечены
[2] собственный вектор найден: lambda = 1337.0
[3] check() пройден, флаг: ctfcup{99aeaf6c1fb1d156e4194be638825e6f}
[4] sha256 = a25dc7ca...cc124442 -> OK
[5] бинарник отвечает: The seal breaks. Carry what you brought to the gate.
```

## 9. Паттерны для похожих заданий

Проверка флага почти всегда попадает в один из нескольких шаблонов. Опытный реверсер узнаёт шаблон по 3–5 характерным инструкциям и сразу достаёт подходящий решатель, не вычитывая весь дизассемблер.

### Таблица 5. Типовые предикаты проверки флага

| Паттерн проверки | Как узнать в дизасме | Чем решать |
|---|---|---|
| Сравнение с эталоном | `strcmp`/`memcmp` или посимвольный цикл с константой | Чтение строки из `.rodata` |
| Посимвольные условия | Цепочка `cmp byte ptr`, таблица подстановок | Собрать по байту, z3 |
| XOR / перестановки | `xor` в цикле, таблица ключа | Обратный проход, крипто-пара |
| Хеш (MD5/SHA/свой) | Константы K/init, 64 раунда, `bswap` | Сверить константы, брутфорс малой энтропии |
| Арифметика входа | Суммы/произведения, система уравнений | z3, линейная алгебра |
| Матрица / лайнал | `imul`-циклы по NxN, попарные сравнения | `numpy.linalg.eig`, sympy |
| VM / байткод | Цикл декодера, switch по опкодам | Эмулятор на python, angr |

### Ловушки, которые чаще всего портят готовое решение

- **Подменённые константы хеша.** Всегда сверяйте `K`/`init` с эталоном: изменённая таблица делает `hashlib` бесполезным.
- **Знак и порядок байтов.** int64 против uint64, little-endian против big-endian (`bswap` перед раундами SHA-256).
- **Переполнение.** Моделируйте арифметику точно: в `mmm` значения до 2141 × 126 × 40 свободно помещаются в int64, но в других заданиях встречается усечение до 32 бит.
- **Собственный вектор определён с точностью до знака и масштаба** — проверяйте оба знака и перебирайте масштабы, а не только «красивые».
- **Float-сравнения.** numpy возвращает приближения; финальный вердикт выносите только в целочисленной арифметике.
- **Формат флага.** Длина, префикс и алфавит (`ctfcup{32 hex}`) резко сужают перебор — используйте это как ограничение решателя.
