# Чек-лист перед публикацией райтапа

Прогоняй перед каждым коммитом лабы/машины. Пункты родились из реального
ревью репозитория — пункт 2 ловит то, что уже случалось (пустые блоки кода
в csrf-конспекте).

## Контент

- [ ] **1. Why it works заполнен.** Ментальная модель, а не «сделал и получилось».
- [ ] **2. Нет пустых код-блоков.** Проверка:
      `rg -n -A1 '^```' README.md` — между двумя оградами не должно быть
      пустой строки сразу после ```.
- [ ] **3. Язык подсветки указан** в каждой ограде: ```http, ```bash, ```html, ```python.
- [ ] **3a. Код-блоки структурно целы:** закрывающая ``` на отдельной строке
      (не приклеена к тексту), каждая ограда закрыта, ограда ```lang не
      болтается внутри открытого блока. Всё это ловит
      `python3 tools/check_titles.py` — категории F и G; чини G сначала,
      она ломает рендер на GitHub и даёт фантомы в F.
- [ ] **3b. Райтап соответствует шаблону:** шапка заполнена (Платформа /
      Категория / Статус / Дата), есть TL;DR → Steps → Why it works →
      Defense, нет пустых секций, битых внутренних ссылок и остатков
      текста-заглушки. Ловит `python3 tools/check_writeups.py`:
      H/I/K/L/M — блокирующие, J/W1–W3/N — предупреждения (план "по одному
      в день").
- [ ] **4. Флаги замаскированы** (хвост через `...REDACTED`) — для живых CTF.
      Для PortSwigger/HTB-лаб ответы можно оставить: это учебные платформы.
- [ ] **5. Defense-блок есть** — как закрыть дыру правильно, конкретным механизмом.
- [ ] **6. Статус в шапке переведён** из `draft` в `done`, когда райтап дописан —
      иначе он числится черновиком в дашборде и в README события.
      Массово: `python3 tools/typ2readme.py --mark-done` (заглушки не тронет).
- [ ] **7. Ничего личного в скринах:** токены сессий своих, домены, имена — закрыть/обрезать.

## Структура

- [ ] **8. Имя папки** `NN-краткое-имя`, внутри `README.md` + `EXPLANATION.md` + `figN.png`.
- [ ] **9. Скрины сжаты** (<300KB каждая; `pngquant` или встроенный экспорт Burp PNG-8).
- [ ] **10. Классовый README** обновлён строкой в таблице Labs
      (или запусти `python3 tools/generate_index.py` — сделает сам).
- [ ] **11. Корневой индекс перегенерирован:** `python3 tools/generate_index.py`.
- [ ] **11a. Конспекты Typst конвертированы:** писал райтап в `.typ`? —
      `python3 tools/typ2readme.py --status done` сделает README.md рядом
      с конспектом и сразу пометит готовым (заглушки README заменит,
      готовые райтапы не тронет — глянь `--list`, если сомневаешься).
      Проверь потом картинки/математику глазами (замечания скрипт печатает).
- [ ] **11b. Легаси-README со шапкой:** писал README руками до внедрения
      шаблона (hackthebox, bootcamp, solarctf, kubok...)? —
      `python3 tools/ensure_header.py --list` покажет файлы без шапки,
      `python3 tools/ensure_header.py "portswigger/**" --status done`
      добавит шапку (статус и дату выбираешь сам по группам).

## Структура репозитория

- [ ] **14. Имена корневых папок.** Сезон/год/раунд зашиваются в ИМЯ
      корневой папки, а не в подпапку: `flare-on-2014/`, `standoff-bootcamp-7/`,
      `liga-ctf-r1-2026/` — тогда generate_index сам выведет красивое
      название события и не примет «2014» за категорию.
- [ ] **15. Два класса корней.** CTF-событие: `<event>-<year>[-rN]/
      <category>/<task>`. Платформа-тренажёр: `hackthebox/<machine>`,
      `portswigger/<vuln>/<NN-slug>`, `picoctf-trainings/<cat>/<diff>/<task>`.
- [ ] **16. Материалы задач** (исходники, архивы, образцы) — в
      `<task>/files/`, чтобы walk_tasks не нашёл в них лишние README.
- [ ] **17. Свалки запрещены:** `_unsorted/` раскладывается по категориям
      при первой возможности. Чужие разборы (материал для подготовки) не
      отдельная свалка, а `alternate-solution.md` рядом с собственной
      задачей — так один таск живёт в одном месте.
- [ ] **18. Перемещения — только `git mv`,** все переименования одним
      коммитом: `[meta] unify top-level structure`.

## Коммит

- [ ] **19. Формат:** `[<класс>|<платформа>] суть` — пример:
      `[csrf|portswigger] token not bound to session: bypass via request omission`.
      Служебные: `docs:`, `chore:`, `fix:`.
- [ ] **20. Ссылки живые:** на таск, на references, на связанные лабы.
