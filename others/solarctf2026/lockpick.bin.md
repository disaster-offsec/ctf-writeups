# Локик — реверс FPGA bitstream

**Флаг: `SOLARCTF{5pl1t_l0ck_g0es_brr}`**

## Кратко

Дана конфигурация `lockpick.bin` — bitstream Lattice iCE40-1k устройства с 32-битным ключом разблокировки. Восстанавливаем Verilog-netlist, находим комбинацию входов для разблокировки и симулируем схему. Флаг появляется **на восьми выходных линиях во время работы**, а не в статичном конечном состоянии.

## 1. От bitstream к логике

Файл имеет размер 32 220 байт. Прелюдия `FF 00 00 FF 7E AA 99 7E` (синхропоследовательность `7E AA 99 7E`) указывает на bitstream iCE40. Энтропия 1.6 бит/байт, ASCII-строк нет. Для разбора подходят открытые инструменты Project IceStorm (`iceunpack`, `icebox_vlog`):

```sh
iceunpack lockpick.bin lockpick.asc
icebox_vlog lockpick.asc > lockpick.v
```

В среде без готовых бинарников IceStorm распаковка была написана на Python — порт логики `icepack.cc` (младший нибл байта команды = длина payload, классы 0x00/0x10/0x20/0x50/0x60/0x70/0x80/0x90, побитовая раскладка CRAM/BRAM). Встроенная проверка CRC-16-CCITT сошлась: `crc=0x0000 OK` — разбор корректен. Чип: iCE40 1k (CRAM 332×144, BRAM 64×256, 1031 единичный бит — таблица ~256 байт).

В восстановленном netlist — 961 нет, 813 комбинационных assign, 105 триггеров и один `SB_RAM40_4K` с `READ_MODE=1`. Анализ связей дал назначение входов:

| Сигнал | Пин |
|---|---|
| Тактовый вход | `io_6_0_1` |
| Сброс, активный высокий уровень | `io_0_8_0` |
| Запуск проверки, enter | `io_5_17_1` |
| 32 бита ключа | остальные входы |
| Индикатор разблокировки | `io_2_0_1` |

## 2. Восстановление ключа

Одного завершения FSM недостаточно: состояние done достигается и с неверным ключом, а мигалки на выходах приходят в «успешное» состояние при любом ключе — это таймер, не проверка. Поэтому исследуем именно выход `io_2_0_1`.

Его логический конус в конечном состоянии разворачивается в булеву формулу над входными пинами (AST-парсер выражений `X if C else Y` + свёртка констант финального состояния). Условие `unlock = 1` решается через Z3 — решение **ровно одно**. Полученный набор входов затем проверяется полной симуляцией.

В единицу нужно установить:

```text
io_0_5_1   io_0_6_0   io_0_6_1   io_10_0_0
io_13_4_0  io_13_6_1  io_13_8_0  io_13_8_1
io_5_0_0   io_6_17_1  io_7_17_1  io_9_0_0  io_9_0_1
```

Остальные 19 ключевых входов — нули. При соглашении «бит i соответствует i-му ключевому пину в лексикографически отсортированном списке» это `0x308A653C`. Это **условное представление ключа**, а не флаг: без исходных имён `key[31:0]` нельзя считать такое число авторским порядком битов (порядок задавал constraint-файл автора `.pcf`, которого в задании нет). Верификация полным прогоном: reset → ключ на входы → импульс enter → ~60 тактов → `io_2_0_1 = 1` (устойчиво), дисплей 0xD7, done=1.

## 3. Чтение флага: две важные детали

### Правильная модель RAM

Для симуляции написан cycle-accurate интерпретатор netlist'а (топологическая сортировка комбинационной логики + триггеры + BRAM; семантика сверена с Yosys `cells_sim.v`). В режиме чтения 1 значение `RADDR[8]` выбирает чётные либо нечётные биты 16-битного слова. Маска обозначает **исключаемые** биты:

```python
mask = 0xAAAA if r8 == 0 else 0x5555
rdata_i = word & (~mask & 0xFFFF)
```

Изначальный вариант `word & mask` выбирал противоположные биты и портил середину сообщения. После чтения пары битов сворачиваются в чётные линии `RDATA`:

```text
RDATA[2k] = |RDATA_I[2k+1:2k]
```

Ещё одна ошибка прежнего неверного анализа — произвольный порядок восьми display-выходов (см. ниже). Декодирование полного потока не требует XOR.

### Правильный порядок выходной шины

Порядок физических пинов не совпадает с порядком ASCII-битов. Известный префикс `SOLARCTF` позволяет восстановить перестановку восьми линий. Среди вариантов, согласующихся с префиксом, вариант без инверсий даёт целиком печатаемую строку с ожидаемыми скобками и известным хвостом.

Биты символа **от младшего к старшему**:

```text
0: io_5_17_0
1: io_3_0_0
2: io_4_0_0
3: io_0_3_0
4: io_4_0_1
5: io_2_0_0
6: io_0_2_0
7: io_0_2_1
```

После сброса и импульса enter каждый символ удерживается два такта. Считываем циклы `1, 3, …, 57`, где цикл 0 — первый такт после импульса запуска. Получаем 29 символов. **Нельзя просто удалять подряд идущие одинаковые байты:** в конце флага есть настоящие повторяющиеся буквы `rr`.

### Воспроизводимая проверка

После восстановления netlist'а и модели (шаги 1–3) проверка сводится к следующему скрипту (Python 3.12, без сторонних пакетов; `Sim` — собственный интерпретатор netlist'а: `set_inputs`, `tick`, `val`):

```python
ONES = set('''
io_0_5_1 io_0_6_0 io_0_6_1 io_10_0_0
io_13_4_0 io_13_6_1 io_13_8_0 io_13_8_1
io_5_0_0 io_6_17_1 io_7_17_1 io_9_0_0 io_9_0_1
'''.split())

# ASCII bits 0..7.
DATA = '''io_5_17_0 io_3_0_0 io_4_0_0 io_0_3_0
          io_4_0_1 io_2_0_0 io_0_2_0 io_0_2_1'''.split()

s = Sim()
s.set_inputs(**{p: int(p in ONES) for p in s.IN})
s.set_inputs(io_0_8_0=1, io_5_17_1=0)
s.tick()
s.set_inputs(io_0_8_0=0, io_5_17_1=1)
s.tick()

result = []
for cycle in range(59):
    s.set_inputs(io_5_17_1=0)
    s.tick()
    if cycle % 2 == 1:
        result.append(sum(s.val[p] << bit for bit, p in enumerate(DATA)))

flag = bytes(result)
assert flag == b'SOLARCTF{5pl1t_l0ck_g0es_brr}'
assert s.val['io_2_0_1'] == 1
print(flag.decode())
```

Проверенный вывод:

```text
SOLARCTF{5pl1t_l0ck_g0es_brr}
Verified: 29 ASCII bytes from corrected simulation; unlock=1.
```

## Флаг

```text
SOLARCTF{5pl1t_l0ck_g0es_brr}
```

Флаг воспроизведён локально из выходного потока схемы; принятие платформой на момент написания не подтверждено.

## Что было важно

- Правильный ключ ещё не является флагом: он позволяет получить нужный выходной поток.
- Смотреть нужно на переходный процесс, а не только на конечный выход.
- Ошибка в инверсии RAM-маски сохраняла часть сообщения, но искажала другую часть.
- Известное окончание `l0ck_g0es_brr}` предоставил пользователь. Оно помогло проверить полную строку, но само по себе не определяло её начало.
- Текст флага не хранится в bitstream: проверены BRAM (все 512 Б), LUT-инициализации, сырой файл, XOR/ADD/SUB-варианты и перестановки сегментов дисплея.
