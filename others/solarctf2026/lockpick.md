# lockpick.bin — FPGA bitstream, 32-bit unlock key (reverse / hardware)

## Условие
Перехвачен bitstream устройства, требующего 32-битный ключ разблокировки. Размер файла — 32220 байт.

## Решение

### 1. Идентификация
Прелюдия `FF 00 00 FF 7E AA 99 7E` — Lattice iCE40. Энтропия 1.6 бит/байт, ASCII-строк нет.

### 2. Распаковка
Инструментов IceStorm под рукой не было (icepack — C++), поэтому формат (младший нибл байта команды = длина payload, классы 0x00/0x10/0x20/0x50/0x60/0x70/0x80/0x90; CRAM/BRAM побитовая раскладка) перенесён в чистый Python. Контрольная сумма CRC-16-CCITT, зашитая в bitstream, сошлась (`crc=0x0000`) — разбор корректен. Чип: iCE40 1k (CRAM 332×144, BRAM 64×256, 1031 единичных бит = таблица ~256 байт). Результат — ASC-представление в тайловом формате IceStorm.

### 3. Netlist
Через `icebox_vlog` из Project IceStorm (chipdb-1k генерируется `icebox_chipdb`) получен Verilog-netlist: 961 нет, 813 комбинационных assign, 105 триггеров, 1 SB_RAM40_4K.

### 4. Симулятор
Написан cycle-accurate интерпретатор netlist'а: топологическая сортировка комбинационной логики + триггеры + BRAM по семантике модели BRAM из библиотеки симуляции yosys (READ_MODE=1: байт собирается из лайнов RDATA, выбор чётных/нечётных по RADDR[8]).

Разведка чёрным ящиком:
- входы: 32 бита ключа, `io_6_0_1` — клок, `io_0_8_0` — сброс, `io_5_17_1` — «enter»;
- после нажатия enter: 8 раундов скремблинга ключа → 13 чтений таблицы по фиксированному маршруту → 8 раундов обновления состояния → результат;
- мигалки на выходах приходят в «успешное» состояние `n308` при ЛЮБОМ ключе — это таймер, а не проверка;
- настоящий индикатор — выход `io_2_0_1`: в финальном состоянии FSM он является чистой комбинационной функцией ровно 32 входных пинов.

### 5. Соль
D-конус `io_2_0_1` развёрнут в AST с парсингом условных выражений `X if C else Y` и свёрткой констант финального состояния. Получена булева функция f от 32 бит ключа. SMT-решатель z3: `f = 1` имеет **ровно одно** решение.

### 6. Ключ
```
io_0_5_1 = io_0_6_0 = io_0_6_1 = io_10_0_0 = io_13_4_0 = io_13_6_1 =
io_13_8_0 = io_13_8_1 = io_5_0_0 = io_6_17_1 = io_7_17_1 = io_9_0_0 = io_9_0_1 = 1
остальные 19 ключевых пинов = 0
```
В соглашении bit_i = i-й пин в string-alphabetical порядке: **0x308A653C**.

Верификация полным прогоном симулятора: reset → ключ на входы → импульс enter → ~56–60 тактов → `io_2_0_1 = 1` (устойчиво), дисплей 0xD7, done = 1.

### 7. Флаг
Текст флага не хранится в bitstream: проверены BRAM, инициализации LUT, сырой файл (включая бит-serial MSB/LSB), однобайтовые и двухбайтовые XOR/ADD/SUB, паддинги из keystream'ов прогона и перестановки сегментов дисплея. Флаг — это ключ в hex-записи, а порядок бит определяется constraint-файлом автора, которого нет. Наиболее вероятные кандидаты (по убыванию вероятности):

1. `SOLARCTF{0x308A653C}` / `SOLARCTF{308a653c}` — алфавитный порядок пинов (конвенция инструментария);
2. `SOLARCTF{a0653827}` — пины по возрастанию номера TQ144, key[0] = pin23 (LSB-first);
3. `SOLARCTF{e41ca605}` — то же, key[31] = pin23 (MSB-first).

Задание отмечено как решённое по ключу, но порядок бит в строке флага однозначно не подтверждён. Наиболее вероятен первый вариант по конвенции инструментария.

## Инструменты
Python (собственные распаковщик, симулятор и SAT-обвязка), z3, Project IceStorm (icebox), исходники yosys как справочник семантики iCE40 BRAM.
