# venti — writeup

> Эта балканская станция выходила в эфир по ночам, музыку на ней не ставили, однако с ее
> помощью можно было научиться созданию даже летного симулятора. Запись, которую вы держите,
> датирована девятнадцатым апреля тысяча девятьсот восемьдесят седьмого года.

Файл: `ventilator303.wav` (PCM, 16 бит, моно, 44100 Гц, 168 с).

**Флаг:** `SOLARCTF{YuG0sl4v1a-Galaks1ja-DIY-Z1L0G80Z}`

Решение одной командой: `python3 solve.py ventilator303.wav`.

---

## 0. Разбор легенды

- «Балканская станция, ночной эфир, без музыки» — это **«Вентилатор 202»**, передача Радио Белград (Югославия, 1980-е). По ночам она передавала программы для домашних компьютеров прямо в эфир: слушатели записывали передачу на кассету и потом загружали её в компьютер.
- «Летный симулятор» — отсылка к тому, что через эфир распространяли и программы, и обучающие материалы. Кроме того, с этой передачей связана история **Galaksija**, югославского компьютера, который собирали своими руками.
- Дата **19.04.1987** позже окажется ключом шифрования (`0x19870419`).

Отсюда гипотеза: в WAV лежит кассетная запись программы.

## 1. Структура аудио

Смотрим среднюю амплитуду по секундам, затем длительности периодов между переходами через ноль:

| Время, с      | Что там                                                        |
|---------------|-----------------------------------------------------------------|
| 0.0 – 3.0     | чистый тон 1000 Гц (период 44.1 сэмпла)                        |
| 3.0 – 12.0    | тихий шум, энергия в основном ниже 1 кГц                       |
| 12.0 – 15.0   | пилот-тон 1000 Гц                                              |
| **15.0 – 157.6** | **данные: частотная манипуляция (FSK) на 1200 / 2400 Гц**   |
| 157.6 – 160.6 | тон 1000 Гц                                                    |
| 161 – 163.5   | тихий шум                                                       |
| 164 – 166     | тон 425 Гц                                                     |
| 166 – 168     | почти тишина                                                    |

Шум и тон 425 Гц для решения не понадобились, я их не разбирал.

Спектр участка данных: пики ровно на 1200 и 2400 Гц. Периоды бывают ~36.75 сэмпла (1200 Гц) и ~18.4 сэмпла (2400 Гц). Это похоже на Kansas City Standard / CUTS на 1200 бод:

- `0` — один период 1200 Гц,
- `1` — два периода 2400 Гц,
- длительность одного бита = 1/1200 с = **36.75 сэмпла**.

## 2. Ловушка: переходы через ноль «плывут»

Первая попытка — классифицировать периоды по переходам через ноль (как это делают утилиты для ZX). Она даёт мусор. Последовательность периодов выглядит, например, так:

```
15s : 18 20 36 18 19 36 ...         <- нормально
20s : 32 18 24 31 19 24 ...         <- 37 и 18 «перетекают» друг в друга
120s: 37 28 18 27 29 18 18 19 27 28 ...  <- 28/27 — уже не отличить
```

Суммы соседних периодов при этом сохраняются (`31+24 ≈ 37+18`). Сдвигается только момент перехода через ноль на стыке частот, причём величина сдвига медленно меняется по ходу записи. Похоже, при переключении частоты фаза сигнала рвётся (два генератора без непрерывной фазы) либо по пути ей что-то портит. В любом случае измерять длину периодов здесь ненадёжно.

## 3. Демодуляция по слотам

Поскольку скорость фиксирована (1200 бод), сигнал режется на слоты по 36.75 сэмпла. В каждом слоте считается корреляция с 1200 Гц и с 2400 Гц (один бин ДПФ / Goertzel):

```python
m = (|X(1200)| - |X(2400)|) / (|X(1200)| + |X(2400)|)
bit = 1 if m < 0 else 0
```

Сдвиг начала слотов подбирается по максимуму медианы `|m|` на первых двух секундах. После этого все ~171 тыс. бит разделяются чисто: минимальный запас `|m|` равен 0.63.

Получившийся поток:

```
000000000 0101010101...0101 (преамбула ~2400 бит) 0011010101010100010100111...
```

## 4. Кадры: UART 8N1

Перебираем длину кадра и смещение и ищем позицию, где у каждого кадра первый бит 0, а последний 1. Подходит **10 бит, ровно одно смещение, 100% кадров**. Это 8N1: стартовый бит 0, 8 бит данных младшим вперёд, стоповый бит 1.

Декодированные байты начинаются с текстового заголовка:

```
UUVENTILATOR-303 TAPE v1
NAME: GALAKSIJA-DEMO
FORMAT: ZXTAP
LEN: 16659
CSUM: 88D9

<16659 байт .tap>  88 D9  UUUUUU...
```

`CSUM` — это CRC-16/CCITT-FALSE (полином 0x1021, начальное значение 0xFFFF): `binascii.crc_hqx(tap, 0xFFFF) == 0x88D9`. Совпало.

## 5. TAP-файл ZX Spectrum

| # | Блок                                   | Размер |
|---|----------------------------------------|--------|
| 1 | заголовок: Program `GALAKSIJA`, autostart 10 | 19 |
| 2 | BASIC                                  | 163    |
| 3 | заголовок: Bytes `GALAKSIJA `, адрес 32768, длина 16448 | 19 |
| 4 | машинный код                           | 16450  |

XOR-суммы всех блоков верные. BASIC после детокенизации:

```basic
10 BORDER 1: PAPER 1: INK 6: CLS
20 PRINT AT 10,8; FLASH 1;"VENTILATOR-303"
30 PRINT AT 12,8;"LOADING FOR THOSE WHO WAIT"
40 LOAD "" CODE
50 RANDOMIZE USR 32768
```

Машинный код: полезных из 16448 байт только первые 1070 (`0x8000–0x842D`), остальное — заполнитель `'Z'`. Строки внутри: `VENTILATOR-303`, `GALAKSIJA DEMO`, `YOU TAPED US RIGHT`. Самого флага открытым текстом нет.

## 6. Реверс Z80

Дизассемблировал вручную (код небольшой). Основной поток выполнения:

```
8000  call 808C        ; очистка экрана, атрибуты 0x16
8003  ld hl,830C
8006  ld (5C7B),hl     ; UDG -> свои символы для рамки
8009  call 8103 / 8154 ; рамка
800F  call 81B0        ; мигание бордюра + щелчки
8012  ld hl,837D
8015  call 81D5        ; мелодия через ROM BEEPER (03B5)
8018  ...              ; печать строк в строках 4, 6, 8
807D  call 82A2        ; <<< вывод флага
8080  ld hl,839D / call 81D5   ; вторая мелодия
8086  xor a / out (FE),a / ei / jr $
```

### Генератор псевдослучайных чисел, `0x8202`

32-битное умножение сдвигами и сложениями. Множитель кладётся в память побайтно: `6D 4E C6 41` = **`0x41C64E6D`** (1103515245). После цикла к результату прибавляется `0x3039` (12345):

```
state = state * 1103515245 + 12345  (mod 2^32)     ; LCG из glibc/ANSI C rand()
```

Состояние хранится по адресу `0x83C4` (little-endian).

### Вывод флага, `0x82A2`

```
82A2  ld hl,83D4 / ld de,83C4 / ld bc,4 / ldir   ; seed = 19 04 87 19 -> 0x19870419
82AD  xor a / ld (83C2),a                         ; i = 0
82B0  ld a,(83C2) / cp 2B / ret z                 ; 43 символа
82B8  call 8202                                   ; state = LCG(state)
82BB  ld a,(8403+i) / xor (83C6)                  ; enc[i] ^ ((state >> 16) & 0xFF)
82CA  ld (83C3),a
82CD  ld a,(83D8+i)                               ; позиция p = perm[i]
82D8  cp 21 / jr c,...                            ; p < 21 -> строка 13, столбец 5+p
                                                  ; иначе  -> строка 15, столбец 5+(p-21)
82F0  call 80A7                                   ; печать символа
82FB  call 03B5                                   ; «бип»
8302  call 81F9                                   ; задержка
8305  inc i / jr 82B0
```

Флаг по одному символу «впечатывается» в случайные позиции экрана, каждый со звуком. Данные лежат так:

- `0x83D4` — начальное значение `19 04 87 19` (та самая дата из легенды),
- `0x83D8` — таблица перестановки из 43 байт (перестановка чисел 0..42),
- `0x8403` — 43 зашифрованных байта.

## 7. Расшифровка

```python
state = 0x19870419
for i in range(43):
    state = (state * 1103515245 + 12345) & 0xFFFFFFFF
    flag[perm[i]] = enc[i] ^ ((state >> 16) & 0xFF)
```

```
SOLARCTF{YuG0sl4v1a-Galaks1ja-DIY-Z1L0G80Z}
```

Флаг получен повторением процедуры на Python. В эмуляторе ZX Spectrum программа не запускалась.

## Цепочка

```
WAV --(FSK 1200/2400 Гц, 1200 бод, демодуляция по слотам)--> биты
    --(UART 8N1, LSB first)--> заголовок "VENTILATOR-303 TAPE" + .tap (CRC-CCITT)
    --(ZX Spectrum TAP)--> BASIC-загрузчик + CODE @ 32768
    --(реверс Z80)--> LCG glibc, seed = 19.04.1987, XOR + перестановка
    --> флаг
```
